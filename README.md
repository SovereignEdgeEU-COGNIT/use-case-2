# Use Case 2 - Wildfire Detection

This repository is a collection of all the software needed to offload functions for the wildfire use case (use-case 2) and to analyze the data generated by a sample TT Fire device.

This repository contains the following folders:

- `example`: Where the software and the data for the demos are stored. This directory also contains a `requirements.txt` file to run the demos. See [Demos](#demos)
- `FireUC`: The folder that has to be included in the COGNIT VM image in order for it to run. This folder also contains a `requirements.txt` for the COGNIT VM environment, and a *pre-trained neural network model* in TensorFlow format imported in the function. See [Setting up the image](#setting-up-the-image)
- `dataset`: Where a sample dataset can be found. It contains bot the dataset and some python scripts to parse the data. See [Datasets](#datasets)

## Neural network model

The pre-trained neural network model used for this test can be found at the following [link](https://github.com/tobybreckon/fire-detection-cnn). Minor changes have been performed to the provided software to adapt it to our needs.

## Setting up the image

The virtual machine requirements to run the image recognition function are a memory size of at least 3.072 GB and a disk size of 8 GB. Additionally, the host CPU must support SSE4.1 instructions and the VM template CPU mode must be in "host-passthrough" mode.

To set up the image, upload the contents of the FireUC folder to the *VM* in `/root/userapp` and rename the `model` folder to `InceptionV1-OnFire`.
Then, activate the virtual environment (see [serverless-runtime](https://github.com/SovereignEdgeEU-COGNIT/serverless-runtime)):

```sh
source /root/serverless-runtime/serverless-env/bin/activate
```

The `libGL` library (required for the installation of `opencv-contrib-python`) can be installed on openSUSE distribution through the following commands:

```sh
zypper install Mesa-libGL1
zypper install libgthread-2_0-0
```

Finally, the requirements listed into `/root/userapp/requirements.txt` can be installed:

```sh
pip install -r /root/userapp/requirements.txt
```

## Demos

To run both demos ensure that a file called `cognit.yml` is required. The file requires two parameters required by the device client framework:

- `api_endpoint`: `https://cognit-lab-frontend.sovereignedge.eu`
- `credentials`: Colon separated user and password used by the device client access the Cognit frontend.
See [device-runtime-py](https://github.com/SovereignEdgeEU-COGNIT/device-runtime-py) for more info.

### Geographical model

The statistical model (`uc2_fire_map_async.py`) represents a geographical simulation a fire. When starting the program a dashboard will load on a browser allowing the user to select the map where the fire will take place, the wind direction and speed. As the parameters are adjusted devices will be placed randomly in the selected area and an additional random point will be selected as the starting location of the fire. Once the simulation is started two ellipses will appear. An inner red one showing the current fire spread, and an outer yellow one to show the distance the distress signal will reach (used for activating nearby devices). During each timestep all devices inside the inner ellipse will offload to COGNIT a picture of a forest fire, while all devices in the outer ellipse will report a picture of a forest. All function offloads will be done asynchronously.

To run this demo, an additional settings file called `settings.toml` is required. This file had three sections, `general`, `map`, and `common-paths`. The `general` section contains 4 different options:

- `number_of_devices`: The number of devices on the map (mutually exclusive with `device_spacing`)
- `device_spacing`: The spacing between devices when placing them in a grid (mutually exclusive with `number_of_devices`)
- `device_trigger_radius`: The trigger radius of each device in meters
- `simulation_steps`: The number of steps for the simulation

The `maps` and `common-paths` sections contain other sections that are either related to the location of files on the disk or parameters that can be modified in the dashboard.

### Statistical model

The statistical model (`uc2_fire_stat_async.py`) simulates a fire spread in a statistical manner. A fire starts at the center of a gird and has a chance to spread to nearby tiles. As time goes on the chance of spreading to nearby tiles increases. The function offload to COGNIT is done in an asynchronous manner.

## Datasets

A dataset of sample data similar to what is produced by the TT Fire can be found in the `dataset` directory.
The main difference between the provided sample data and the data produced by the TT Fire is that the sample dataset contains one RBG picture per hour,
instead of capturing an image only when sensors detect a fire. This was done as a way to test the RBG images without requiring a fire.
In the folder there are 8 files:

- 3 python files to process the data:
  - `extract_IR_images.py`: To extract the images produced by the infrared camera
  - `extract_JPG_images.py`: To extract the images produced by the RGB camera
  - `extract_sensor_data.py`: To extract the sensor data to a CSV
- 4 data files, one for each sample device
- `requirements.txt` with the modules used by the python scripts

Generally each data file contains a row per data received. Each row is a list of semi-colon-separated values and the first values are always (in order):

- timestamp
- device serial number
- record type
Then depending on the record type, different data follows.
